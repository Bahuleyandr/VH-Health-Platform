# NL12-S3 500-Bed SLO Re-Baseline Record

Use this template for the operator-approved 500-bed run. Store completed copies
under `output/loadtest/<YYYY-MM-DD>/` with the raw k6 summary, Prometheus
snapshot JSON, and Grafana screenshots. Do not commit filled evidence bundles.

Required guardrails:

- `LOADTEST_500BED_CONFIRM=I_HAVE_APPROVAL_AND_SYNTHETIC_DATA`
- `PRODUCTION_SHAPED_ENV=confirmed`
- `OWNER_APPROVED_BY` records the owner or change ticket.
- `TARGET_ENVIRONMENT` names the production-shaped target.
- `SYNTHETIC_PATIENT_UIDS` contains only seeded synthetic patients.
- Full profile does not target laptop Postgres or real patient data.

## Capacity Assumptions

| Assumption | Baseline |
| --- | --- |
| Licensed beds | 500 |
| Target occupancy | 85% (425 active inpatients) |
| Ward model | 12-24 wards, with mixed general, ICU, emergency, theatre, lab, radiology, and pharmacy traffic tags |
| OPD volume | 1,200-1,600 visits/day compressed into the run window |
| Med-pass pressure | Up to 150 concurrent VUs pulling due/overdue MAR lists plus synthetic vitals writes |
| Bed-board pressure | Up to 45 concurrent VUs on bed list, occupancy, and available-bed reads |
| Admin fan-out | Up to 20 concurrent dashboard users reading daily ops, IP occupancy, lab TAT, and OPD snapshots |
| SLO probe | 5 VUs checking `/health/metrics` for server-side agreement |

These VUs are not "beds". They are compressed concurrent operator actions that
represent the highest-risk slices of a 500-bed hospital day.

## SLO Decision

| SLO | Current target | Observed | Decision |
| --- | ---: | ---: | --- |
| Chart/list read latency | p95 < 400 ms |  | Keep / change |
| Clinical write latency | p95 < 800 ms |  | Keep / change |
| 5xx error rate | < 1% k6, 99.95% availability budget |  | Keep / change |
| Throttled rate | < 5% |  | Keep / change |

Decision notes:

- If k6 latency and Grafana latency diverge, classify as edge/network/ingress.
- If both diverge, inspect backend slow-query logs and CNPG pressure first.
- If routine deploys burn the 99.95% availability budget, record whether the
  remedy is topology hardening or an owner-approved SLO target change.
- Do not lower or raise SLO targets without owner sign-off in the change ticket.

## Deferrals

- Real production or pilot load remains an operator ceremony.
- Filled evidence bundles stay in `output/loadtest/` and are not committed.
- Any SLO target change must be a separate governed config/docs change.

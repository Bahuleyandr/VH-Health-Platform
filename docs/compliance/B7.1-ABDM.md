### ABDM-M2-03 — FIDELIUS-compatible HI bundle encryption

| Control | Evidence |
|---|---|
| Encryption implementation | `apps/backend/src/services/abdm/abdmCrypto.js` — per-transfer ephemeral X25519 key pairs + 32-byte nonces; HKDF-SHA256 (salt = first 20 bytes of nonce XOR, IV = last 12 bytes); AES-256-GCM with appended tag |
| Data-push enforcement | Data-push path refuses to send plaintext; requests without valid HIU key material are marked FAILED |
| HIU public key capture | Migration 288 (`hiRequest` table): HIU key material captured per request |
| Unit test | `abdmCrypto.js` tested against RFC 7748 X25519 vector + independent AES-GCM re-derivation |
| Gap | Byte-level interop sign-off against ABDM sandbox HIU pending sandbox credentials (ABDM-G2) |

### ABDM-M2-04 / M2-05 — FHIR R4 HI types

## 4. `[flagged: procurement]`

> The following items are gated on external registration, government action, or
> commercial engagement. All platform-side code is built and ready. These items
> cannot be closed by a code commit alone.

1. **`[flagged: procurement]` ABDM sandbox credentials** — Register at
   `sandbox.abdm.gov.in`, obtain `ABDM_CLIENT_ID` / `ABDM_CLIENT_SECRET`, choose
   HIP/HIU ID, set `ABDM_CALLBACK_URL` + `ABDM_CALLBACK_SECRET`. Seal as
   Kubernetes SealedSecrets (not in ConfigMap). Then set `ABDM_ENABLED=true`.

2. **`[flagged: procurement]` ABDM bridge registration** — Once credentials exist,
   register the bridge URL and HIP/HIU capabilities against the sandbox gateway.
   Requires NHA approval of the exact facility/software endpoint.

3. **`[flagged: procurement]` ABDM M1/M2/M3 certification suites** — Run against
   the sandbox with NHA observers. Book after bridge registration and M2 dry run.
   M3 (HIU) runs after M1+M2 pass and consent-request UX is piloted.

## 2. Control → Evidence Mapping

### NABH-IMS-01 / IMS-02 — Medical records: unique ID, complete, timely

| Control | Evidence |
|---|---|
| Unique patient identifier | `users` table: `uid` (UUID, unique per patient, cross-facility stable); MRN generated per encounter |
| Canonical clinical record structure | `patient_encounters`, `clinical_timeline_events`, `clinical_audit_events` (migration 269 `269_canonical_clinical_platform.sql`); every clinical action writes to the canonical timeline |
| Mandatory record elements | `clinicalNotesService.js` (notes + diagnosis), `vitalsChartService.js` (vitals with anomaly alerts), `orderEntryService.js` (CPOE), `admissionService.js` (admission/transfer/discharge) — all atomic since WS0 B0.5 |
| Prescriptions | `prescriptions` table + `medicationAdministrationRecords` (migration 004); dose, route, frequency, prescriber ID all required fields |

### NABH-IMS-03 / IMS-04 — Protection from unauthorised access / retention

| Control | Evidence |
|---|---|
| Role-based access control | `src/config/routeWrapper.js::wrapAutoRBAC` — all clinical routes gated by `requireRole()`; role matrix CI-enforced (`roleMatrix.spec.test.js`) |
| Multi-tenant isolation | RLS policies on 283 tables (WS1 B1.1/B1.2); FORCE RLS; NOSUPERUSER `vhhealth_runtime` role (WS0 B0.2, migration added to CNPG spec) |
| PHI field-level encryption | `apps/backend/src/utils/fieldEncryption.js` — AES-256-GCM envelope encryption (enc:v2) with per-record DEK + KEK wrap (`fieldKeyProvider.js`); `SENSITIVE_USER_FIELDS` and `SENSITIVE_STAFF_FIELDS` enumerated |
| Data at rest | PostgreSQL 17 on CNPG with RKE2 on-prem; node-level disk encryption is hospital infrastructure responsibility |
| Retention controls | `094_gdpr_erasure_audit_tables.sql` — erasure audit; `india_compliance_evidence` ledger (`300_india_deployability_controls.sql`) tracks `DPDP_RETENTION_SCHEDULE` |

### NABH-IMS-05 / IMS-06 — Role-based access; confidentiality

| Control | Evidence |
|---|---|
| Unique user IDs | Staff: `employees` table with `employee_id`; JWT carries `uid` (UUID) + `role`; `jti` per token |
| Access control model | `src/config/rbacConfig.js` + `routeWrapper.js::wrapAutoRBAC`; per-route role gates; default-deny (no wildcard allow) |
| PHI access logging | `src/middleware/phiAccessMiddleware.js::phiAccessLogger()` applied to appointments, records, investigations, prescriptions, pharmacy, EMR, clinical workflows, documents, radiology, dietary, theatre, blood-bank, referrals, ABDM |
| Confidentiality training | Gap — see NABH-G5 |

### NABH-IMS-07 — Electronic records: authentication + audit trail

| Control | Evidence |
|---|---|
| Authentication with unique user ID | JWT HS256 signed with `jti`; staff login: employee ID + password; admin: TOTP MFA; patient: Firebase OTP; single auth middleware `jwtMiddleware.js` |
| Audit trail of access | `clinical_audit_events` hash-chained audit (migration 282 trigger + `documentIntegrityService.verifyAuditChain`); per-tenant advisory locking; 13-case tamper test (WS4 B4.6) |
| Audit trail of changes | All clinical writes produce one `clinical_timeline_events` row + one `clinical_audit_events` row in the same transaction (WS0 B0.5) |
| Non-repudiation | `jti` in every token; `requestId` logged per request; blacklist prevents replay |
